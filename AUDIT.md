# FGB Academy — Codebase Audit

> Generated by a static read-only audit across backend (Go/Gin), frontend (SvelteKit + Svelte 5), data layer (Postgres + pgvector), and infrastructure (Docker Compose, Caddy, embeddings service).
>
> Findings cite file:line for verification. No builds or tests were run; a few items (marked *verify at runtime*) would benefit from reproduction before fixing.

---

## Severity legend

- 🔴 **Critical** — exploitable by anyone, or causes data loss. Fix immediately.
- 🟠 **High** — exploitable by an authenticated user, or correctness/reliability bugs with real impact.
- 🟡 **Medium** — bugs or weaknesses with bounded impact, or poor practice.
- 🟢 **Low** — code hygiene, dead code, minor UX/a11y.
- 📦 **Missing feature** — foundational capability that is absent.

## 🔴 Critical (fix immediately)

| # | Finding | Location |
|---|---|---|
| **C1** | **Password hashing is broken.** Static salt `"testsalt"` shared by all users + Argon2id memory is `19*1024` **bytes** (not KB) — ~1000× weaker than OWASP minimum. Rainbow tables work against the whole DB at once. No params/salt encoded → cannot be re-tuned without forcing every user to reset. | `backend/functions/hash_functions.go:19-25` |
| **C2** | **Password-reset poisoning.** Reset link is built from the client-controllable `Origin` header. Attacker sends `Origin: https://evil.tld` and steals the victim's token when they click the emailed link. | `backend/password_reset/handler.go:62-67` |
| **C3** | **Path traversal in uploads.** `GenerateFilePath` only strips spaces/brackets — not `/` or `..`. A `filename="../../etc/passwd.pdf"` writes anywhere the process can. | `backend/documents/handler.go:63` + `backend/worker/worker.go:339-352` |
| **C4** | **Hardcoded prod DB credentials.** `POSTGRES_PASSWORD=password` in both compose files; baked into backend `DATABASE_URL`. | `compose.yaml:6-8`, `compose-production.yaml:8-10` |
| **C5** | **No pgvector index** on `document_chunks.embedding`. Every coach query and AI-generation retrieval does a brute-force linear scan over all chunks. | `backend/database/schema.sql:92`, `query.sql:78-84` |
| **C6** | **Production Dockerfile runs as root**, isn't multi-stage, and `compose-production.yaml` bind-mounts source over the built binary while `CMD` is `go run main.go` — production runs from bind-mounted source, not a built artifact. | `backend/Dockerfile.prod`, `compose-production.yaml:54-56` |

### Proposed fixes

- **C1**: Replace `MakeHash`/`ValidateHash` with `github.com/alexedwards/argon2id` (or hand-roll `$argon2id$v=19$m=65536,t=3,p=2$<b64-salt>$<b64-hash>`). OWASP minimum: memory ≥ 19 MiB, time=2, parallelism=1, random 16-byte per-user salt. Plan a re-hash-on-login migration: existing hashes are unusable after the change, so on next successful login with the *old* `ValidateHash`, immediately re-hash with the new scheme and update the row. Alternatively force a password reset for all users.
- **C2**: `appURL := os.Getenv("APP_URL")`; ignore the `Origin` header entirely. The mailer already reads `APP_URL` from env (`mailer/mailer.go:39`), so the wiring exists. If multi-tenant origins are needed, validate against a server-side allowlist.
- **C3**: In `GenerateFilePath`, run `clean = filepath.Base(clean)` and reject anything still containing `..`. Better: generate a fully random name (UUID) and store only the original extension.
- **C4**: Move to `${POSTGRES_PASSWORD:?required}` in both compose files via a gitignored `.env`. Rotate the password immediately. Use a separate, stronger prod password.
- **C5**: `CREATE INDEX ON document_chunks USING hnsw (embedding vector_cosine_ops);` (HNSW preferred over IVFFlat — no training step, works well at small scale). Re-create after bulk data loads.
- **C6**: Multi-stage Dockerfile (`FROM golang:1.26 AS builder` → `CGO_ENABLED=0 go build -o /out/app .` → `FROM gcr.io/distroless/static-debian12` → `COPY /out/app` → `USER 65532:65532`). Remove the source bind-mount from `compose-production.yaml`.

## 🟠 High

### Security / Authorization

| # | Finding | Location |
|---|---|---|
| **H1** | **IDOR on learning-path enrollments.** `DropEnrollment` and `UpdateProgress` mutate any enrollment by ID with no `user_id` check. Any user can mark anyone's course 100% complete → triggers certificates. | `backend/learning_paths/handler.go:380-430` |
| **H2** | **IDOR on notifications.** `MarkRead` query has no `user_id` filter — any user can suppress anyone's notifications. | `backend/notifications/handler.go:55-67`, `query.sql:244` |
| **H3** | **No rate limiting** on `/api/login`, `/api/setup`, `/api/forgot-password`. Brute force + email bombing possible. | `backend/main.go:85,106`; `password_reset/handler.go:33,89` |
| **H4** | **Cookie `Secure: false`** and no explicit `SameSite`. Session leaks over any HTTP hop. | `backend/main.go:263-265` |
| **H5** | **Login timing oracle.** User-not-found returns immediately, no dummy hash → email enumeration. | `backend/app/login.go:17-33` |
| **H6** | **`/api/setup` TOCTOU + permanently exposed.** Concurrent requests can create two admins; route never disables after first admin. | `backend/app/auth.go:54-92` |
| **H7** | **`crypto/rand.Read` error ignored** in token generation. On entropy failure tokens are zero-filled and predictable. | `backend/functions/hash_functions.go:13` |
| **H8** | **Frontend has no server-side role guards.** Pages like `/user-management`, `/audit-log`, `/analytics`, `/content-studio` rely entirely on hidden nav. Any authenticated user can navigate directly. All 8 role-gated `+page.server.ts` files lack a role check. | `src/routes/(app)/{user-management,audit-log,analytics,content-studio,...}/+page.server.ts` |
| **H9** | **`SaveProgress` trusts client-reported `completed` + `score_pct`.** Learner can POST `{completed:true, score_pct:"100"}` and get a gold certificate without answering anything. | `backend/lessons/handler.go:306-418` |
| **H10** | **Enrollment capacity race.** Check-then-insert is not atomic; concurrent requests can exceed capacity. | `backend/enrollments/handler.go:135-177` |

### Reliability

| # | Finding | Location |
|---|---|---|
| **H11** | **Workers have no retry / DLQ / job timeout.** Failed document/AI jobs are marked `failed` permanently after one attempt. AI generation can hold resources for many minutes per job with no wall-clock cap. | `backend/worker/worker.go`, `backend/ai/jobs.go` |
| **H12** | **Stale `*gin.Context` read in goroutines.** Coach handler (and audit logging) launches goroutines that read from a pooled `gin.Context` after the handler returns — undefined behavior under load. | `backend/coach/handler.go:85-92` |
| **H13** | **4 Chart.js instances leak on every navigation** away from `/analytics` (no `.destroy()` in cleanup). The dashboard chart is correct; analytics isn't. | `src/routes/(app)/analytics/+page.svelte:101-385` |
| **H14** | **Polling `$effect` stacks intervals.** In `content-studio` the effect re-runs and overwrites `pollInterval` without clearing the previous → multiple intervals fire in parallel. | `src/routes/(app)/content-studio/+page.svelte:30-42` |

### Proposed fixes

- **H1/H2**: Add `user_id` filter to the underlying sqlc queries (`DropLearningPathEnrollment`, `UpdateLearningPathEnrollmentProgress`, `MarkNotificationRead`), or fetch-then-verify ownership before mutating. Return 403 on mismatch.
- **H3**: Add IP + email-keyed rate limiting. Suggested: 5 logins/min/(IP+email), 3 resets/hour/email, 10 setups/hour/IP. Use `golang.org/x/time/rate` (in-memory, single-instance) or Redis-backed limiter for HA.
- **H4**: Read `secure` from env (`SECURE_COOKIE=true` in prod). Build the cookie explicitly with `SameSite: http.SameSiteLaxMode`.
- **H5**: On user-not-found, run a dummy `ValidateHash` against a precomputed hash to equalize timing before returning the error.
- **H6**: Wrap check+insert in a serializable transaction or `pg_advisory_xact_lock(hashtext('setup'))`. Gate the route behind `ALLOW_SETUP=true` env, or only register the handler when `CheckIfFirstUser()` is true at startup.
- **H7**: Make `MakeTokens() (string, error)`; on `err != nil` fail closed (refuse login/reset).
- **H8**: Add role enforcement in each role-gated `+page.server.ts` using `data.user` from `(app)/+layout.server.ts`. Even better: centralize via a route-to-roles map in `hooks.server.ts`. Plumb the user into `event.locals.user` (currently `App.Locals` is commented out in `app.d.ts`).
- **H9**: Compute `Completed` and `ScorePct` on the server from `item_progress` rows (compare answers, count correct), not from the request body. Treat client `completed` as a hint at most.
- **H10**: Wrap check+insert in a transaction with `SELECT ... FOR UPDATE` on the course row, or use `INSERT ... WHERE (SELECT count(*) ...) < $capacity`.
- **H11**: Add `attempts int` and `last_error text` to `course_generation_jobs` and `documents`. Retry transient (network/5xx) errors up to N times with backoff. Wrap `processJob` in `context.WithTimeout(ctx, 15*time.Minute)`. Add an admin UI to re-queue failed jobs.
- **H12**: Extract `uid := c.GetInt64("user_id")` before launching goroutines; pass the scalar in. Use `context.WithTimeout(context.Background(), N)` not the request context.
- **H13**: Capture each Chart instance and destroy in the returned cleanup function: `return () => charts.forEach(c => c.destroy())`.
- **H14**: Clear the existing interval inside the `$effect` before setting a new one, or guard so the effect only starts polling when active and cleans up when inactive.

## 🟢 Low / hygiene

- Dead code: `backend/auth_module/hashing.go` (duplicates broken hash), `backend/home_handler/login.go` (empty), unused `totalScore` block in `certificates/handler.go:171-178`.
- `app.d.ts` `App.Locals` commented out — no type safety on `event.locals.user`.
- `<button onclick={() => goto(...)}>` used where `<a href>` would give free preload + middle-click support.
- Accessibility: chat lacks `aria-live="polite"`, custom radio inputs have no visible focus ring, icon-only buttons lack `aria-label`.
- `/test` route shipped to production — delete or gate behind `import.meta.env.DEV`.
- `learning_preferences` has a duplicate `ALTER TABLE ... ADD COLUMN theta` (line 191 repeats line 186).
- `scripts/01_certificates_badges_v1.sql` references wrong DB name (`fgb_lp` vs actual `example_db`) and its content is already duplicated in `schema.sql:364-417`.
- `vite.config.ts` proxy target hardcoded to `http://backend:5555` (compose-only).
- `EXPOSE 5713` typo in `Dockerfile.frontend:10` (should be 5173).
- `course_generation_jobs.id` is `text` PK with UUID string — native `uuid` type would be smaller and indexed natively.
- `users.role` CHECK allows spaces (`'end user'`, `'content creator'`); parallel `user_roles.role` has no CHECK — they can drift.
- No structured logging (`log/slog` would be a drop-in upgrade); no request IDs.
- Embedding response uses `float64` everywhere then converts to `float32`; model is natively f32.
- `CommandPalette` debounce handle not cleared on destroy.
- `home_handler.GetDashboard` has dead `_ = enrolledAtValid` pattern.
- `ListMyEnrollments` does an N+1 course fetch for `settings` (should be a JOIN).
- `departments.BulkEnroll` doesn't create `enrollments` rows or send emails — inconsistent with `enrollments.BulkEnrollUsers`.
- `UpdateUserRoles` allows self-demotion / last-admin lockout.
- Logout is vulnerable to logout-CSRF (low impact).

## 📦 Missing features (foundational gaps)

| Capability | Impact | Suggested approach |
|---|---|---|
| **Migration tool** | `runMigrations` is a no-op; schema evolution is ad-hoc `alter table` appends with no rollback. | Adopt `golang-migrate` or `atlas`. Move `schema.sql` body + `scripts/01_*.sql` into versioned migration files. |
| **Soft deletes** | Every delete is hard + CASCADE. Audit logs reference IDs that no longer exist; certificates lose their backing data. | Add `deleted_at timestamptz` to parent tables; filter reads. |
| **Rate limiting** | None anywhere. AI endpoints can saturate DeepSeek; auth endpoints allow brute force. | `gin-contrib/limits` or token-bucket middleware per user + per IP. |
| **Observability** | Only `log.Printf`. No metrics, traces, or request IDs. | `log/slog` for structured logs; Prometheus metrics (request latency, job queue depth, LLM/embedding latency); optional OpenTelemetry. |
| **CI/CD** | No `.github/workflows/`. The checks in `AGENTS.md` (`npm run check`, `go vet`) aren't enforced. | Add a CI workflow running `npm run check`, `npm run build`, `go vet ./...`, `go build ./...`. |
| **Backups** | `pgdata` is the only copy of all data. | Schedule `pg_dump` to S3-compatible storage; test restore. |
| **Security headers** | No HSTS, CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy. | Small Gin middleware. |
| **Password change endpoint** | Only admin-create + forgot-password exist. | Add `POST /api/me/password` (requires current password). |
| **Email verification** | Accounts can be created with arbitrary emails. | Add `email_verified` column + verification token flow. |
| **MFA / 2FA** | Single-factor only. | TOTP via `pquerna/otp`. |
| **Session management UI** | Users can't see/revoke other active sessions. No rotation on login. | Add `GET /api/me/sessions`, `DELETE /api/me/sessions/:id`. Rotate on login. |
| **Graceful shutdown** | `r.Run(":5555")` — no SIGTERM handling; in-flight requests + worker die abruptly. | Wrap in `http.Server`, call `Shutdown(ctx)` on SIGTERM; drain worker queue. |
| **Idempotency keys** | Duplicate course-generation requests create duplicate courses. | Accept `Idempotency-Key` header on `POST /api/courses/generate`. |
| **Frontend i18n** | All copy is hardcoded English. | SvelteKit i18n. |
| **Frontend PWA / offline** | No service worker, no `manifest.json`. | Add for mobile-first LMS use case. |
| **File upload progress** | `content-studio` upload uses `fetch` with no progress events. | Use `XMLHttpRequest.upload.onprogress`. |
| **Dead-letter queue for failed jobs** | Failed documents/AI jobs are stuck in `failed` forever. | Add `failed_jobs` table + admin UI to re-queue. |
| **Frontend pagination UI** | Only `content-repository` and `review-queue` paginate. `user-management`, `audit-log`, `learning-paths` don't. | Add search/filter/pagination to all list pages. |
| **Frontend retry / request cancellation** | Only one server load implements retry. No client-side retry or `AbortController` on chat. | Standardize an API client wrapper. |

## Recommended fix order

1. **C1, C2, C3** — exploitable by anyone, no special tools. (C1 requires a re-hash-on-login migration plan.)
2. **C4** — rotate DB password today.
3. **H1, H2, H8, H9** — authorization gaps; an authenticated end user can take over accounts/courses.
4. **H4, H5, H6, H7** — auth hardening bundle.
5. **C5** — single biggest perf win for AI features; one `CREATE INDEX ... USING hnsw`.
6. **C6** — fix production Dockerfile before next deploy.
7. **H11** — worker retries/timeout/DLQ.
8. Medium/low and the foundational gaps (migrations, observability, CI).
